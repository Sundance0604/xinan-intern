# 销售交易日常工作交接

本说明对应项目`projects/西南证券工作内容`。仓库包含可复用代码、业务规则、三张空白模板和合成测试；真实持仓、交易、历史报表、审核记录和腾讯文档配置由原同事通过内部渠道另行交接，不在GitHub。

## 一、项目负责什么

| 工作 | 程序入口 | 自动完成的内容 |
|---|---|---|
| 买入记录 | `scripts/bond_purchase/bond_process.py` | 使用已准备的交易和市场字段生成买入记录，不自动查询DM |
| 当日持仓抓取 | `extract_qq_docs.js` → `json_to_xlsx.py` | 腾讯文档持仓、资金积数两个工作表导出为本地Excel |
| 持仓核对 | `daily_trade_records.py`、`diff_holdings.py` | 对比两日快照，辅助查找买卖变动 |
| 三张表 | `pnl_tables.py` → `template_reports.py` | 成本匹配、已确认付息补计、分类、累计指标及固定模板填充 |
| 持仓提醒 | `holding_days_reminder.py` | 生成本地提醒文本，实际发送需另行授权 |

脚本不能代替交易批次确认、付息通知、税费查询和业务审核。`run_daily.bat`只运行抓取、导出和提醒，不生成三张表；目前没有配置定时任务。

## 二、第一次安装（Windows / PowerShell）

需要Git、Conda、Node.js、Chrome。Python 3.11和Node.js 24已在本机验证。浏览器抓取使用本机Chrome，不会自动下载Chrome或自动登录。

```powershell
git clone git@github.com:Sundance0604/xinan-intern.git
cd "xinan-intern/projects/西南证券工作内容"
conda create -n pavane python=3.11 -y
conda run -n pavane python -m pip install -r requirements.txt
npm --prefix scripts ci
Copy-Item config.example.json config.local.json
conda run -n pavane python -m unittest discover -s tests -v
```

若已有`pavane`环境，跳过创建环境。没有GitHub SSH配置时，可使用仓库网页的HTTPS克隆地址。

编辑`config.local.json`：填写内部交接的腾讯文档链接、两个工作表ID及Chrome可执行文件路径。工作表ID一般来自打开对应标签后的URL `tab=`参数。不要把真实配置提交GitHub。链接需要登录或没有访问权限时，先解决文档授权，不能跳过抓取错误继续计算。

以下命令均在本项目目录执行，不依赖原同事的D盘目录。Conda环境名不同可替换`pavane`。

## 三、每日操作

### 1. 准备本地输入

建议以`local_data/YYYY-MM-DD/`为每日目录。已有`scripts/data/MMDD/`目录也可以继续使用，命令中的路径保持一致即可。

至少准备：

- 当日交易查询：核对结算日期、交易状态、编号、方向、金额及数量；跨文件不要重复计入同一交易。
- 前一交易日持仓：保留实际剩余批次，核实历史卖出已经扣除。
- 前一交易日分类表、盈利表：分别提供历史周数据和“最新数据”中的真实累计值。
- 历史交易目录：文件名采用`MMDD交易查询*.xlsx`；缺少原始买入时补齐记录或核实期初余额，不用0代替成本。
- 当日拆借成本、税费、人工付息通知；多批买入、代缴归属、非最终交易状态按业务确认。

这些输入和当天`output/`都属于本地数据，不提交仓库。

### 2. 抓取当日持仓

```powershell
$day = '2026-01-06' # 示例日期，必须改为实际计算日
$folder = "local_data/$day"
New-Item -ItemType Directory -Force -Path $folder | Out-Null
node scripts/extract_qq_docs.js --config config.local.json --out "$folder/snapshot.json"
conda run -n pavane python scripts/json_to_xlsx.py "$folder/snapshot.json" "$folder/当日持仓.xlsx"
```

检查两个工作表均非空、公式已有计算结果、资金余额覆盖计算日，不能仅凭导出文件存在判断成功。较早抓取的持仓可能尚未更新，交易补齐后必要时重新抓取；先备份人工修订版，不能直接覆盖。

### 3. 处理当日担保买入

先计算并保存金额，持仓J“结算金额”、Q“资本利得”当日暂留空，注明次日补录、待王老师审核。依据交易交收方式识别担保，不只看持仓H标签；部分卖出只处理剩余持仓部分。必须重算持仓汇总再生成盈利表，清空J/Q不会自动修正已经缓存的汇总。该步骤是人工业务流程，当前三表CLI不自动清空持仓或重算腾讯文档的全部源公式。

次日按保存的当日值补录，并核对批次、剩余量及是否已补，不能改用次日价格，也不能将J暂空解释为真实买入成本0。担保券当日已完成卖出结算、持仓次日才删除，属于已确认的录入流程，不能仅凭仍在持仓表便取消当日收益。

### 4. 先检查计算结果

```powershell
$calc = @(
  "$folder/交易查询.xlsx",
  '--date', $day,
  '--prev', "$folder/前日持仓.xlsx",
  '--hold', "$folder/当日持仓.xlsx",
  '--trades-dir', 'local_data/交易记录',
  '--prev-profit', "$folder/前日盈利表.xlsx",
  '--prev-classification', "$folder/前日分类表.xlsx",
  '--chai', '0',
  '--outdir', "$folder/output"
)
conda run -n pavane python scripts/pnl_tables.py @calc --json
```

默认**只纳入“成交确认”**。本次业务明确同意纳入执行中或审批通过时，在`$calc`里增加`'--trade-statuses','成交确认','交易执行中','审批通过'`；不能把上一次同意视为以后日期持续授权。历史成本核验的状态范围另行确认，不随该选项自动改变。

`--json`不会生成Excel。检查`需人工确认`、`代缴待确认`和每券`未匹配完`；任一未解决，不交付正式表。多笔买入用`--choices`指定，代缴归属用`--daijiao-choices`，仅在获准FIFO时使用`--fifo`或已确认的`--replay-costs`。不能只因程序找到买入记录就认定该批尚未被历史卖出消耗。国债当日先卖后买时，不把汇总匹配冒充真实逐笔FIFO配对。

### 5. 补齐税费、付息后生成

税费CLI单位为**万元**，系统“本期贷方、累计贷方”金额为元时除以10000；零值也要明确传0。拆借成本单位元，以负数传入，周四按业务通知确认。本期税费未给时程序沿用前日并提示，不能把沿用值说成今日已核验。

付息与每日持仓估算票息不同，也不是拆借成本。收到经确认的付息通知后，可保存为当日目录`coupons.json`，以下是合成示例：

```json
{
  "date": "2026-01-06",
  "source": "本次人工付息确认记录",
  "payments": {"012345": 1234.56}
}
```

`payments`单位元，代码作为文本保留前导0。需核实通知金额覆盖的批次及是否已入账，再补计一次。当前`--coupons`仅支持已有卖出汇总的券；没有卖出的单独付息、还本、跨日付息或分摊不明应另行核实，不能塞入任意一只卖出券。

```powershell
# 合成示例：本月税费1万元、本年累计2万元；使用时换成实际查询值
conda run -n pavane python scripts/pnl_tables.py @calc --tax-month 1 --tax-year 2
# 本日有经确认的付息时，上一条命令增加：--coupons "$folder/coupons.json"
```

输出为`MMDD盈亏情况.xlsx`、`MMDD每日结算分类.xlsx`、`MMDD销售交易部当日盈利情况.xlsx`。程序从`templates/`读取三张空白模板，正式盈亏表同券一行，逐笔成本与付息字段在`output/_support/`审计文件中保留。重复运行从原始输入重新计算，不能把已补计结果再手工加一遍。

### 6. 复核与交付

- 总结算金额差＝逐券收益（含经确认实收付息）＋拆借成本；收益先按元分勾稽，再转万元。
- **（代缴＋撮合）×10000＋拆借成本＝总结算金额差**。只有分类表不计拆借，盈利表计入。
- 盈利表本年累计＝前日累计＋当日，累计交易量同理；A1当日、B1年末、C1年初，年化公式引用A1－C1。
- 核对税费、日均占资、时点占资、日终持仓；当日担保买入须已按流程排除。收益率使用年内日均占资，不用时点占资替代。
- 付息只补计一次；不要又把实收付息加进估算“票息收入”并重复加到收益。
- 在Excel/WPS打开检查公式重算和显示，金额两位小数、百分数两位；检查截字、空值、错误值以及汇总求和范围。
- 交王老师审核，记录状态。生成本地文件不代表已提交或审核通过。

Python使用openpyxl填充模板，不提供Excel公式缓存计算。Excel/WPS打开后需启用自动计算、保存，再把文件作为次日前日累计输入；如果累计值为空，不能手工填0绕过。桌面agent可使用电子表格引擎重算并检查保存值。

## 四、模板与后续修改

`templates/`三张xlsx均随仓库交接。不要从真实前日报表复制出“带旧数字的模板”。固定格式与更新方法见[模板说明](templates/README.md)。源表格式或指标位置变化时，检查`capture_report_templates.py`与`template_reports.py`后再更新模板。

本地`scripts/data/.../_support/`中的按日临时脚本不随GitHub交接，也不要将其绝对路径或当日金额写入通用代码。日常使用这里说明的公开入口和配置选项。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 抓取失败、登录页、空表 | 核对权限、链接、sheet ID和Chrome路径，保留日志，停止使用不完整快照 |
| 找不到历史买入 | 补齐历史查询或核实期初；不得将缺失成本当0 |
| 持仓J金额与实际交易不同 | 优先核对实际买入交易及历史消耗，不直接套旧快照 |
| 只有本金差额显示负数 | 查是否发生付息或还本，需人工通知确认，不能猜补金额 |
| 清空担保买入J/Q后汇总没变 | 重新计算源表或显式排除后重算缓存，再运行三表 |
| 输出文件被Excel/WPS占用 | 关闭文件后重跑；保留人工修改版备份 |
| 前日累计为空、出现待补收益 | 确认提供真实前日报表，打开计算保存，再读取缓存 |
| 缺主办人提示 | 从业务原文补充`--hosts`，不可用录入员冒充主办人 |

完整业务规则以[成本核验注意事项](成本核验注意事项.md)为准。新同事在首次实盘操作前应完成一次内部已核验日期的复算对比。
